# 崩溃回退 · 完整使用说明

给 DeepSeek Harness（DSH）**桌面版**用的**崩溃自动回退**工具。

装了插件之后 DSH 起不来？它会把配置退回上一个能用的版本、把依赖重新装好、再把 DSH 拉起来。

> **适用对象**：DSH 桌面版的 `desktop` profile（`%USERPROFILE%\.dsh\profiles\desktop`）。
> **仅 Windows**。命令行版 DSH 不适用——依赖对齐那一步用的是桌面版自带的 pnpm。
>
> 图形界面逐项说明见 [GUI.md](GUI.md) · 日志怎么读见 [LOG.md](LOG.md) · 英文技术文档见 [TECHNICAL.md](TECHNICAL.md)。

---

## 一、这是什么

| 问题 | 答案 |
|---|---|
| 它解决什么 | 装插件把 DSH 搞崩、启动不起来 |
| 它怎么解决 | 自动退回上一个能用的配置，重装依赖，重启 DSH |
| 你要做什么 | 装插件**之前**点一下「开关监视」，窗口留着 |
| 平时它占资源吗 | 不占。没在监视时没有任何进程 |
| 怎么卸载 | 删掉整个文件夹，没有残留 |

**DSH 自己没有回退功能。** 插件配置是直接写进配置文件的，一旦装坏，你连界面都进不去，
只能手改 `package.json` 和 `pnpm-lock.yaml`。这个工具就是替你改这两步。

## 二、三步上手

刚用上 DSH、准备装插件，照这三步做：

| 步骤 | 做什么 |
|---|---|
| 1 | **先装好 DSH 桌面版，并启动过一次。** 本工具依赖它，而且需要先有一个"好版本"可退 |
| 2 | 解压到固定位置，双击 `app\dsh-guardian.exe`。没有安装程序、不写注册表、不会自动建快捷方式 |
| 3 | 点 **「打基线」** 记下当前这份好配置 → 点 **「开关监视」** 开始守着 → **窗口别关** |

然后放心装插件。

装完之后：DSH 能正常启动 → 点一次 **「打基线」**（记新基线）→ 点 **「开关监视」** 关闭检查 → 关窗口。

> **窗口就是开关（默认）。** 监视器以 `-ParentPid <本窗口进程号>` 启动，**窗口一关它就退出**；勾上「关窗后继续监视」后不带该参数，关窗也继续跑
> （日志里会记 `resident: exiting (launcher closed)`）。
> 这不是卡住，是刻意的：程序不会在你不知情的情况下留在后台。

## 三、界面上的 8 个按钮

打开后是一行按钮，不用记任何按键：

| 按钮 | 作用 | 什么时候用 |
|---|---|---|
| **打基线** | 把现在这个状态记为一个"好版本"（新增一份，不覆盖旧的） | 装插件**之前**，或确认 DSH 正常之后 |
| **开关监视** | 开 / 关自动监视。**只有"开"的时候才监视** | 装插件前开，装完确认正常后关 |
| **回退** | 打开版本列表，选一个：现在就回退，或只设为以后的目标 | DSH 崩了的时候 |
| **日志** | 看 DSH 最近为什么崩、崩在哪 | **出问题先点这个** |
| **目录** | 浏览 `data\`：快照、日志、诊断报告，可预览文件内容 | 想自己翻文件的时候 |
| **刷新** | 重新读一遍状态（等同 `F5`） | 状态行看着没更新时 |
| **放大结果** | 收起上面的分区，让输出占满整个窗口 | 输出很长想看清 |
| **退出** | 退出程序（监视同时停止） | 用完了 |

![主界面](main-window.png)

### 「当前状态」三行怎么看

| 行 | 含义 |
|---|---|
| **监视中 / 未监视** | `● 监视中 —— 关掉本窗口即停止` = 正在守着（勾了「关窗后继续监视」则显示 `—— 关窗后继续监视`）；`○ 未监视 —— 不占用任何资源` = 什么都没跑 |
| **上次检查** | 上一次检查是多久之前。运行中时应该每隔约 1 分钟刷新 |
| **回退目标** | 当前生效的那个"好版本"。点「打基线」之后这里会变 |

## 四、基线与「回退目标」

**基线 = 六个配置文件的副本。**

```
package.json   pnpm-lock.yaml   cordis.patch.yml
cordis.yml     pnpm-workspace.yaml   compatibility.json
```

| 问题 | 答案 |
|---|---|
| 能存几份 | 想存多少存多少。**旧的永远不会被覆盖** |
| 自动回退用哪份 | 只用其中一份，叫**当前回退目标**，界面上那一行显示的就是它 |
| 默认指向哪份 | 最新打的那一份 |
| 一份多大 | 几十 KB（就是那 6 个文件） |
| 怎么清理 | 点「回退」→ 勾「多选」→ 选不要的 → 点「删除选中版本」 |

### 什么时候需要换回退目标

假设你依次装了插件 A、插件 B，结果 B 让 DSH 崩了：

| 目标指向 | 回退结果 | 适合 |
|---|---|---|
| 最新基线（装 B 之前那份） | **A 留下了** | 只想干掉 B |
| 更早的基线（装 A 之前那份） | **A、B 都没了** | 想回到两个都没装的状态 |

所以**每次装完插件、确认正常后重新打一次基线**，回退点才不会停在太旧的位置。

## 五、点「回退」之后

弹出的是**版本列表对话框**，不是要你输入序号：

![版本选择](versions.png)

| 区域 | 内容 |
|---|---|
| 顶行提示 | 选中一个版本：现在就回退、只设为以后的目标 |
| 筛选按钮 | `全部` / `最近 10 个` / `仅基线` |
| **多选** | 勾上之后列表出现复选框，可一次选多个（**只对「删除选中版本」生效**） |
| 列表列 | 版本 · 状态 · 抓取时间 · 插件数 · 标签 |
| 包含插件 | 选中某一版时，右侧列出它当时装了哪些插件 |
| 底部按钮 | `现在就回退` / `只设为以后的目标` / `删除选中版本` / `取消` |

**两个动作的区别：**

| 按钮 | 效果 |
|---|---|
| **现在就回退** | 立刻把配置恢复到选中的那一版 |
| **只设为以后的目标** | 现在不动，只让它成为**以后**自动回退的目标 |

**回退永远可逆。** 每次回退前，当前的坏配置会先另存到 `data\snapshots\pre-restore-<时间>\`，
需要的时候可以把它当成一个版本来选。

> 如果你选的那一版不是当前生效的，回退后它会**自动变成新的回退目标**——
> 这样之后万一又崩，自动回退会退到你亲手选的地方，不会前后矛盾。

### 如果回退后 DSH 还是起不来

说明**问题不在配置**。这时候：

1. 点「日志」看 DSH 崩溃时的原始报错；
2. 用 `pre-restore-<时间>` 那份切回你原来的配置（回退是可逆的）；
3. 手工卸掉可疑插件，或按日志里的提示处理。

## 六、崩溃了会自动做什么

前提：**窗口开着，且监视是"开"的。**

DSH 启动即崩溃时，它自动完成这一串，你什么都不用做：

| 步骤 | 动作 |
|---|---|
| 1 | 连不上 → 尝试重启 → 又崩 → 重复到达阈值 |
| 2 | 判定为**启动崩溃循环被证实** |
| 3 | 先把崩溃证据存下来（`data\console\`、`crash-evidence-*.json`） |
| 4 | 把你这套**坏配置另存一份**（`pre-restore-<时间>\`，不会丢） |
| 5 | 恢复**上一个好版本** |
| 6 | **自动把依赖重新装好** |
| 7 | 重启 DSH |

正常情况下你只会看到 DSH 自己起来了。

### 三道安全闸门

| 闸门 | 作用 |
|---|---|
| 只在**崩溃循环被证实**时才动手 | 不把"启动慢"误判成崩溃 |
| **同一份配置绝不回退两次** | 防止把同一套坏配置反复退来退去 |
| **总次数硬上限 2 次** | 兜底，不会无限回退 |

### 判定节奏（想调快看这里）

| 参数 | 默认 | 说明 |
|---|---|---|
| `-BootWindowSeconds` | **90 秒** | 一次启动必须等满整个窗口，才可能被算作"短命启动" |
| 日志心跳 | 30 秒 | 判定期间每 30 秒写一行"仍在启动窗口内，暂未下结论"，不会看起来像卡住 |

所以一个**瞬间就死**的 DSH，在头 90 秒里日志仍然显示正在启动，自动回退要再等一轮才触发。
嫌慢就把 `-BootWindowSeconds` 调小（例如 `10`），前提是你的 DSH 正常情况下用不了那么久就能占住端口。

> ⚠️ **轮次间隔必须大于引导窗。** 如果 `-IntervalSeconds` 小于 `-BootWindowSeconds`，
> 每一轮都会被判成"仍在引导窗内"，启动次数根本累积不起来，
> **崩溃循环永远无法成立、自动回退永远不会触发**。这是实测踩过的坑。

## 七、出错怎么查

按这个顺序，三步之内基本能定位：

| 顺序 | 去哪 | 看什么 |
|---|---|---|
| 1 | 点「日志」 | DSH 崩溃时的原始报错，通常已经写明原因 |
| 2 | 点「目录」 | 浏览 `data\`：快照、日志、诊断报告，可预览内容 |
| 3 | 桌面「DSH Guardian 诊断」快捷方式 | 生成一份完整报告（见下） |

详细的日志逐行解释（包括哪些看着吓人其实正常）见 **[LOG.md](LOG.md)**。

### 诊断报告

双击桌面上的 **「DSH Guardian 诊断」**，或者运行：

```powershell
app\dsh-guardian.exe diagnostics
```

它会收集排查所需的全部信息，生成一份中文报告并**自动打开报告和它所在的文件夹**：

```
<工具文件夹>\data\诊断报告\诊断报告-日期-时间.txt
```

报告里包含程序与数据位置、当前模式、监视器状态、回退目标、残留检查、DSH profile 与插件列表、
端口探测结果、全部日志、崩溃证据、快照列表。

**不含**密码、密钥、账号信息，可以放心贴出来。

## 八、命令行用法（可选）

不想开界面时用。命令行动词在 **`dsh-guardian-console.exe`**；
`dsh-guardian.exe` 收到这些词会转发给它，两个写哪个都行。

```powershell
cd app

.\dsh-guardian-console.exe logs         # 看错误日志
.\dsh-guardian-console.exe baseline     # 打基线
.\dsh-guardian-console.exe rollback     # 回退（和界面点「回退」完全一样）
.\dsh-guardian-console.exe preview      # 只显示回退计划，什么都不改（安全预览）
.\dsh-guardian-console.exe arm          # 开始监视（随当前窗口，关窗即停）
.\dsh-guardian-console.exe disarm       # 停止监视
.\dsh-guardian-console.exe on | off     # 同 arm | disarm
.\dsh-guardian-console.exe shortcut     # 重新创建桌面快捷方式
.\dsh-guardian-console.exe diagnostics  # 生成诊断报告
.\dsh-guardian-console.exe probe        # 只探测端口与健康状态
.\dsh-guardian-console.exe help         # 列出全部动词
```

## 十、常见问题

**我不装插件，需要它吗？**
不需要。它只防"装插件导致 DSH 起不来"这一种情况。

**命令行版 DSH 能用吗？**
不能，只针对**桌面版**。修复依赖要调用桌面版自带的 pnpm，那个路径只存在于桌面版安装目录。

**它会不会误判，把我好好的 DSH 退了？**
回退的门槛是"启动崩溃循环**被证实**"：默认要等满 90 秒的引导窗、并观察到连续多次短命启动。
另外同一份配置**绝不会被回退两次**，还有 2 次的硬上限。判定期间每 30 秒写一行日志说明进度，不会静默卡住。

**会不会拖慢 DSH、偷跑后台？**
不会。没有计划任务、没有开机自启项、没有后台常驻。
**窗口就是开关（默认）**：开着才在监视，关掉立即停止；勾上「关窗后继续监视」后关窗也继续跑，需重开窗口点「开关监视」才停。开关一次监视只做一次端口探测，间隔默认 55 秒。

**它读我的会话和密钥吗？**
不读。只碰那六个配置文件，`node_modules` 只做依赖对齐、不删除。
诊断报告也不含密码与密钥。

**回退后 DSH 还是起不来怎么办？**
那说明问题不在配置。点「日志」看 DSH 的原始报错，用 `pre-restore-<时间>` 切回原配置，
再手工卸掉可疑插件。这种情况它会**停止回退也停止重启**，不会无意义地反复拉起 DSH。

**怎么彻底卸载？**
删掉整个工具文件夹就行。没有安装程序、不写注册表、没有计划任务、没有开机自启，
所以删掉即卸载干净。顺手可以把桌面快捷方式一并删除。

**桌面图标不见了？**
进 `app`，运行一次 `dsh-guardian.exe shortcut` 重新创建。程序不会自动往桌面放东西。

**怎么确认它真的没在后台跑？**
看 `data\runtime.pid` 在不在——不在就是没在跑。也可以打开任务管理器搜 `powershell`。

**想自己翻文件、看某个日志的内容？**
点「目录」，内置浏览器可以浏览并预览 `data\` 下的任意文件。

## 十一、已知限制

| 限制 | 说明 |
|---|---|
| **仅 Windows、仅 DSH 桌面版** | 命令行版 DSH 不适用；其他平台不适用 |
| **探测粒度是端口应答** | 判据是"端口有没有在回应"，不是进程内部的偶发错误 |
| **崩溃判定默认要等 90 秒** | 一次启动要等满整个引导窗才可能被判"短命"。嫌慢可调小 `-BootWindowSeconds` |
| **轮次间隔必须大于引导窗** | 否则启动次数累积不起来，崩溃循环永远无法成立、回退永不触发 |
| **窗口必须开着** | 监视器绑在窗口进程上，关掉窗口即停止。这是"平时绝不常驻"的代价，两者不能同时满足 |
| **依赖对齐需要桌面版** | 修复那一步调用桌面版自带的 pnpm，所以只支持桌面版 |

## 十二、端口是自动识别的（不用你改）

探测的端口不是你填的，是它自己找的。识别顺序：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | `-Port` 参数 | 你指定了就用它，跳过识别 |
| 2 | DSH 进程当前监听的端口 | 最可靠——正在接受连接的端口不可能是错的 |
| 3 | `data\port.txt` | 上次识别成功时写下的缓存 |
| 4 | 3080 | DSH 的默认值，最后兜底 |

第 3 条是给崩溃场景准备的：**DSH 崩了进程就没了**，这时只能靠缓存记住上次的端口。
所以 `data\port.txt` 不要删。真要固定端口就用 `-Port`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "app\dsh-watchdog.ps1" -NoStart -Port 19387
```

看到 `DSH healthy` 才算对。

## 十三、要改代码的话

编码相关的坑（Windows PowerShell 5.1 的 ANSI 解码、生成文件要按读取方的编码写）在
**[TECHNICAL.md](TECHNICAL.md)** 里有完整的实测记录，改之前务必看一遍，能省几个小时。

改完 `.cs` 要重新编译：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "app\build.ps1"
```

改完 `.ps1` 至少验证解析与编码（本项目的 `.ps1` 一律保持**纯 ASCII**）：

```powershell
$errs=$null; $null=[System.Management.Automation.Language.Parser]::ParseFile('app\dsh-watchdog.ps1',[ref]$null,[ref]$errs)
$errs.Count                                                    # 必须是 0
([IO.File]::ReadAllBytes('app\dsh-watchdog.ps1') | Where-Object { $_ -gt 127 }).Count   # 必须是 0
```
