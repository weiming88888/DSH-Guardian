# 崩溃回退 · 使用说明

给 DeepSeek Harness（DSH）**桌面版**（Windows 上安装的那个应用）用的**崩溃自动回退**工具。

装了插件后如果 DSH 起不来，它会把配置退回上一个能用的版本、把依赖重新装好、再重启 DSH。

> **适用对象**：DSH 桌面版的 `desktop` profile（`%USERPROFILE%\.dsh\profiles\desktop`）。
> **仅 Windows**。不是通用 DSH 工具——依赖对齐那一步用的是桌面版自带的 pnpm，
> 因为 DSH 命令行会拒绝操作桌面版管理的 profile。详见 [README.zh-CN.md](../README.zh-CN.md)。

> 本文件是**完整细节版**。想先看精简的项目介绍，请回 [README.zh-CN.md](../README.zh-CN.md)。

---

## 最重要的一点

**它平时完全不存在。**

- 没有计划任务
- 没有开机启动项
- 没有后台进程
- **不占用任何内存**

只有你**双击桌面图标打开它、并按 `4` 打开开关**之后，它才开始工作；你**关掉那个黑窗口，它立刻停止**。

---

## 一、怎么打开

双击桌面上的 **「DSH Guardian」**。

> 图标不见了？进 `app`，运行一次 `dsh-guardian.exe shortcut`。
> **快捷方式不会自动创建**——程序不会主动动你的桌面。

打开后你会看到：

```

==========================================================

   2. 回退 / 切换目标   —— 选一个版本：现在回退，或只作以后的目标
   3. 打基线            —— 把当前状态记为一个“好版本”
   4. 自动检查: 关      —— 按此键开关自动回退
   0. 退出
==========================================================

【当前状态】
  监视状态 : 未运行 —— 本程序当前不占用任何资源
  上次检查 : 4 分钟前
  回退目标 : 20260930-084144-known-good

【简易使用流程】
  装插件之前 : 按 4 打开自动检查（变“开”）
  装完插件后 : DSH 能正常启动 → 按 1 或任意键回到菜单 → 按 3 打基线
  平时不用时 : 按 4 关掉，然后关掉本窗口（关掉就完全不运行）

  注意：按 4 之后窗口会进入“监视中”，此时**必须保持窗口开着**。
        关掉窗口 = 停止监视。
==========================================================
profile : C:\Users\<你的用户名>\.dsh\profiles\desktop
data    : D:\DS\崩溃回退\data

请选择:
```

按数字键选，按 `0` 退出。

### 按 `4` 打开之后会发生什么

窗口会变成这样，并且**停在这里**：

```
自动检查：已开启 —— 监视器运行中。

【监视中】本窗口现在必须保持打开。
  关掉本窗口 = 停止监视。
  装完插件、确认 DSH 正常后，按任意键回来打基线并关闭监视。

监视运行中...
```

**这个窗口就是"开关"本身**——它在，监视就在；它关，监视就停。
按任意键回到菜单（监视继续运行），再去按 `3` 打基线、按 `4` 关掉。

### 「当前状态」三行怎么看

| 行 | 含义 |
|---|---|
| **监视状态** | `未运行` = 没在监视，零占用；`运行中` = 正在监视，**此时别关窗口** |
| **上次检查** | 上一次检查是多久之前。运行中时应该每约 1 分钟刷新 |
| **回退目标** | 现在记着的"好版本"是哪一个。按 `3` 打基线后这里会变 |

## 三、四项菜单

| 按键 | 名称 | 作用 |
|:---:|---|---|
| `1` | 查看错误日志 | 看最近为什么崩、崩在哪。**出问题先按这个** |
| `2` | 回退 / 切换目标 | 选一个版本，再决定**现在回退**还是**只作以后的目标** |
| `3` | 打基线 | 把**现在**这个状态记为一个"好版本"（**新增一份，不覆盖旧的**） |
| `4` | 自动检查 | 开关。**只有"开"的时候才监视** |
| `0` | 退出 | 退出（监视同时停止） |

> 早期版本把"回退"和"切换目标"分成 `2`、`5` 两项，但两项都要先选版本、选完才分岔，
> 等于**同一份列表看两遍**，而且得在**看到有哪些版本之前**就决定要干哪件事。
> 现在合成 `2`：**先看版本，再决定动作**。

## 四、关于"好版本"（基线）

### 可以保留多个

每按一次 `3` 打基线，就**新增一份快照，旧的不会被删**。所以你可以攒下多个不同时间点的"好版本"。

### 但自动回退只用其中一份

叫**当前回退目标**。菜单里「回退目标」那一行显示的就是它。默认永远指向**最新**打的那一份。

### 什么时候需要切换目标

假设你依次装了插件 A、插件 B，结果 B 让 DSH 崩了：

| 目标指向 | 回退结果 |
|---|---|
| 最新基线（装 B 之前） | **A 留下了** —— 适合只想干掉 B |
| 更早的基线（装 A 之前） | **A、B 都没了** —— 适合想回到两个都没装的状态 |

**按 `2` 就能选**，列表里会标出哪份是当前生效的：

```
DSH Guardian · 回退 / 切换目标
--------------------------------------------------
选一个版本；下一步再决定是现在回退，还是只让它作以后自动回退的目标。

  1. 20260930-124301-known-good   <== 当前生效
       抓取于 2026-09-30 12:43:01
       含 6 个插件层
  2. 20260930-092135-known-good
       抓取于 2026-09-30 09:21:36
       含 6 个插件层

  0. 取消（什么都不做）

输入序号（0 或回车 = 取消）:
```

选完版本后，弹窗让你决定**要做什么**：

| 按钮 | 效果 |
|---|---|
| 【是】 | **现在就回退**到这个版本 |
| 【否】 | 不回退，只把它设为**以后**自动回退的目标 |
| 【取消】 | 什么都不做 |

所以"只想换个目标、现在别动"就选【否】——不需要另一个菜单项。

### 会不会越攒越多？

会。每一份只有几十 KB（就是那 6 个配置文件）。想清理就删 `data\snapshots\` 里不要的文件夹——
**但别删当前生效的那一份**，否则自动回退会找不到目标（会拒绝回退并告警）。

### 名字后面的 `-2` 是什么

快照名精确到秒（如 `snap-20260930-134944-known-good`）。如果你在**同一秒内**又打了一次基线，
第二份会自动变成 `snap-20260930-134944-known-good-2`。

这是**故意的**：绝不覆盖已存在的快照。`pre-restore-` 备份同理。

正常使用（两次操作间隔超过 1 秒）不会出现后缀。

## 五、回退 / 切换目标（细节）

按 `2` 会列出**全部**已保存的快照，你自己挑——**不受"当前目标"限制**：

```
DSH Guardian · 回退 / 切换目标
--------------------------------------------------
选一个版本；下一步再决定是现在回退，还是只让它作以后自动回退的目标。

  1. 20260930-124301-known-good   <== 当前生效
       抓取于 2026-09-30 12:43:01
       含 6 个插件层
  2. 20260930-092135-known-good
       抓取于 2026-09-30 09:21:36
       含 6 个插件层

  0. 取消（什么都不做）

输入序号（0 或回车 = 取消）:
```

选定后：

1. 屏幕先显示**你选中的是哪个版本**、抓取时间
2. 弹窗让你决定**要做什么**（见表）
3. 只有选【是】才会写盘：先把**当前配置另存**到 `snapshots\pre-restore-时间\`，再恢复你选的那一份

**关键一点：如果你选的是"是"且它不是当前生效的那份，回退后它会自动变成新的回退目标。**
这样之后万一又崩，自动回退会退到你亲手选的地方，不会前后矛盾。

### 怎么取消

回退流程里**有三道取消机会**，任何一道都能让你全身而退：

| 位置 | 怎么取消 | 结果 |
|---|---|---|
| **选版本的选单** | 输入 `0`，或直接按回车 | 什么都不做 |
| **动作弹窗** | 点【取消】 | 什么都不做 |
| **动作弹窗** | 点【否】 | 不回退，只把它设为**以后**自动回退的目标 |

确认弹窗是这样：

```
要回退到下面这个版本吗？

20260930-084144-known-good
抓取于 2026-09-30 08:41:44

【是】立即回退
【否】先不回退，只把它设为以后自动回退的目标
【取消】什么都不做
```

**弹窗上直接关掉窗口（×）也等于取消**，不会执行任何操作。

### 界面上的两处提示

| 提示 | 意思 |
|---|---|
| `<== 当前生效` | 自动回退当前用的就是这一份 |
| `（它不是当前回退目标，回退后会自动把它设为新目标）` | 你选了另一份，回退后目标会跟着变 |

### 选错了怎么办？

- 序号输错想反悔 → 输 `0` 或直接回车
- 弹窗里点【取消】→ 什么都不做
- 真退错了 → 用 `pre-restore-时间` 那份切回来（**回退永远可逆**）

## 六、日常怎么用

### 平时什么都不用管

它不运行，零占用。

### 要装插件时

```
第 1 步：打开 DSH Guardian，按 4
         → 窗口进入“监视中”，保持它开着
第 2 步：去装插件（窗口别关）
第 3 步：装完、DSH 能正常启动后：
         按任意键回到菜单  →  按 3 打基线  →  按 4 关掉  →  关掉窗口
```

**三个要点：**

- **按 4 之后窗口会进入"监视中"并停在那里**，这是正常的，不是卡住。
- **监视期间别关窗口**，关掉 = 停止监视。
- **第 3 步别漏打基线**，否则回退点还停在旧配置上，下次回退会把你后来装的插件一起退掉。

> 记成一句话：**按 4 打开并留着窗口，装完打基线，再按 4 关掉。**

### 忘了关就直接退出会怎样

如果你还开着监视就按 `0` 退出，它会**先弹窗提醒你**"退出会停止监视"，确认后才退出并停掉监视器。不会静默地把你丢在无保护状态。

## 七、崩溃了会怎样

前提：窗口开着，且自动检查是"开"。

DSH 启动即崩溃时，它自动做这些，你什么都不用做：

1. 连不上 → 尝试重启 → 又崩 → 重复 3 次
2. 判定为"启动崩溃循环"
3. 先把**崩溃证据**存下来
4. 把你那套**坏配置另存一份**（不会丢）
5. 恢复**上一个好版本**
6. **自动把依赖重新装好**
7. 重启 DSH

正常情况下你只会看到 DSH 自己起来了。

### 如果自动回退也没救回来

它会**停止回退**（同一套配置绝不回退第二次），**并且停止重启**（回滚都没用，重启更没用），然后在日志里写明：

```
AUTO-ROLLBACK DID NOT RESOLVE THE CRASH LOOP.
  Relaunching stopped: the rollback did not help, so another restart cannot either.
```

意思是：**问题不在配置**。按 `1` 看日志，里面有 DSH 崩溃时的原始报错。

## 九、几个要知道的点

### 1. 它从不主动运行

没有计划任务、没有启动项。关掉窗口 = 立刻停止。
想确认它没在跑：看 `data\runtime.pid` 在不在——不在就是没在跑。

### 2. 它不会弹任何窗口

程序是**无控制台类型**，系统层面就不具备创建窗口的能力。后台运行时屏幕上不会出现黑窗口。

### 3. 端口是自动识别的（不用你改）

探测的端口**不是你填的，是它自己找的**。识别顺序：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | `-Port` 参数 | 你指定了就用它，跳过识别 |
| 2 | DSH 进程当前监听的端口 | 最可靠——正在接受连接的端口不可能是错的 |
| 3 | `data\port.txt` | 上次识别成功时写下的缓存 |
| 4 | 3080 | DSH 的默认值，最后兜底 |

第 3 条是给崩溃场景准备的：**DSH 崩了进程就没了**，这时只能靠缓存记住上次的端口。
所以 `data\port.txt` 不要删。真要固定端口，用 `-Port`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "app\dsh-watchdog.ps1" -NoStart -Port 19387
```

看到 `DSH healthy` 才算对。

### 4. 它只动这 6 个配置文件

`package.json`、`pnpm-lock.yaml`、`cordis.patch.yml`、`cordis.yml`、`pnpm-workspace.yaml`、`compatibility.json`

**不会碰**你的会话记录、账号凭据。依赖目录 `node_modules` 也不删，只按恢复后的版本重新对齐。

### 5. 回退永远可逆

每次回退前，坏配置都会先另存到 `data\snapshots\pre-restore-时间戳\`。

### 6. 安全闸门

- 同一套配置**最多自动回退 2 次**，且**相同配置不会回退第二次**
- 回退失败后**停止重启**，不会无意义地反复拉起 DSH

## 十、命令行用法（可选）

不想用菜单时：

```powershell
cd "app"

.\dsh-guardian.exe baseline    # 打基线

```

## 十一、发现 bug 怎么反馈

### 最快的方式：双击桌面「DSH Guardian 诊断」

它会自动收集排查所需的全部信息，生成一份**中文报告**（约 10 KB），并且会**自动打开报告和它所在的文件夹**：

```
D:\DS\崩溃回退\data\诊断报告\诊断报告-日期-时间.txt
```

**把这份报告发给我就行**（直接拖进对话，或复制全文粘贴）。

> 报告写在**工具文件夹内部**，不往桌面丢东西。文件名带时间戳，多次运行不会互相覆盖。
>
> 如果双击后窗口一闪而过或报错，请把**那个报错文字**发给我——启动器出问题时报错信息本身就是最重要的线索。

报告里包含（全中文标注）：
- 程序与数据位置、**主程序类型**（判断会不会弹窗）、**脚本编码是否正常**
- 当前模式、监视器是否在跑、上次检查时间、回退目标
- 是否残留计划任务/启动项/多余进程
- DSH profile 状态、已装插件列表、端口探测结果
- **全部日志**：追踪日志、运行日志、事件记录
- 崩溃证据（如果有）
- 快照列表

**不含**密码、密钥、账号信息，可以放心发。

### 我自己反馈时最需要的三件事

如果报告不方便发，告诉我这三样我也能定位大部分问题：

| 需要什么 | 从哪拿 |
|---|---|
| **你怎么操作的、期望什么、实际发生什么** | 你的描述 |
| **运行日志** | `data\watchdog.log` 最后 50 行 |
| **追踪日志** | `data\exe-trace.log`（记录每次启动/监视器状态） |

出问题时按 `1` 看错误日志，那里通常已经写明了原因。

### 反馈时请顺带说明

- **是哪个动作出问题**：按 `4` 开关、按 `3` 打基线、崩溃后没自动回退、窗口有异常……
- **DSH 当时的状态**：正常启动 / 起不来 / 崩溃循环
- **有没有改过端口**（现在会自动识别；真要固定就用 `-Port`）

## 十二、常见问题

**问：平时它占多少内存？**
答：**零**。没有进程在跑。只有你打开窗口并按 `4` 之后才有监视进程。

**问：我关了窗口，还会继续监视吗？**
答：不会。这是故意的——关窗口就是不想让它跑了。

**问：怎么确认它还在监视？**
答：菜单里看「监视状态」是不是"运行中"，以及「上次检查」的时间是不是刚刚。
也可以看文件 `data\last-tick.json` 的时间，应该每约 1 分钟刷新。

**问：怎么确认它真的没在后台跑？**
答：`data\runtime.pid` 不存在 = 没在跑。
也可以按 `Ctrl+Shift+Esc` 打开任务管理器，看有没有相关 powershell 进程。

**问：桌面图标不见了？**
答：进 `app`，运行 `dsh-guardian.exe shortcut` 手动创建一次。

**问：它会自己往我桌面上放东西吗？**
答：**不会。** 程序启动和运行时完全不碰桌面，快捷方式只有在你显式运行 `shortcut` 命令时才创建。

**问：回退后还要手动做什么？**
答：不用。依赖对齐已自动完成。只有日志里出现 `ACTION NEEDED` 才需要动手。

**问：打基线要花多久？**
答：瞬间完成，只复制 6 个小配置文件，不碰 `node_modules`。

## 十三、以后要改代码的话（重要约束）

这个工具踩过两次**同一类坑**，都是文件编码问题。修改代码前请务必知道：

### 1. `.ps1` 脚本里**不能直接写中文**

Windows PowerShell 5.1 读取**没有 BOM** 的 `.ps1` 时，按系统 ANSI 代码页（简体中文是 GBK）解码。
所以源码里直接写中文会被解码坏掉，**整个脚本解析失败**。

**本项目的做法**：所有 `.ps1` 保持**纯 ASCII**。
需要输出中文时（如诊断报告），把中文以 **UTF-8 十六进制**存进脚本，运行时再解码——
`collect-diagnostics.ps1` 里的 `$ZH` 表和 `T` 函数就是干这个的。

改完务必验证：

```powershell
# 这条必须输出 0
$b=[IO.File]::ReadAllBytes('app\dsh-watchdog.ps1')
($b | Where-Object { $_ -gt 127 }).Count
```

### 2. 生成的 `.cmd` / `.vbs` 必须按"读取方认的编码"来写

注意：规则**不是**"生成的脚本里不能有中文"，也不是"必须纯 ASCII"。早先按这个理解
写代码，造成过一个**静默失效**的 bug，而且同一个坑踩了两次——重启路径会生成两个
文件，两个都带着 `data\` 的路径：

启动包装 `.cmd` 和隐藏启动器 `.vbs`。如果程序放在中文目录下（例如 `D:\DS\崩溃回退\`），
用 `-Encoding ascii` 写文件时所有中文会变成 `?`，于是：

```
.cmd  -> cmd.exe 真的去写 D:\DS\????\data\console\console-<时间戳>.log
.vbs  -> wscript.exe 直接报"系统找不到指定的路径"
```

真正的 `data\console\` 一直是空的——而那恰恰是崩溃证据（stderr）该落的地方。
整个过程不报任何错，因为那个写歪的日志确实写成功了。

实测结论（这也是为什么编码要**运行时判断**、不能写死）：

| 控制台代码页 | ANSI，无 BOM | 带 BOM 的 UTF-8 |
|---|---|---|
| 936（中文 Windows 默认） | **可用** | 失败（BOM 被当成命令名的一部分） |
| 65001（UTF-8） | 失败（GBK 字节不是合法 UTF-8） | **可用** |

所以每个生成文件都用**它自己的读取方**认的编码：

| 文件 | 读取方 | 写法 |
|---|---|---|
| `launch-captured-*.cmd`、`post-rollback-install-*.cmd` | `cmd.exe` | 控制台代码页（`Get-CmdEncoding` 判断：ANSI，或 65001 下的 UTF-8+BOM） |
| `launch-captured-*.vbs` | `wscript.exe` | **UTF-16 LE + BOM**（无论代码页是什么都认） |
| `mode.json`、`state.json`、`*.jsonl`、诊断报告 | PowerShell / 主程序 | UTF-8（一直没问题） |
| `runtime.pid` | PowerShell | ASCII（只有数字） |

另外包装脚本用 `cmd.exe /d` 启动，避免 AutoRun 命令偷偷改掉代码页；
两个生成点现在遇到含 `?` 的路径都会**直接拒绝**，而不是生成一个指向别处的脚本。

**一句话原则：凡是"生成出来给别的程序读"的文件，必须按读取方使用的编码来写，
并且用读回的方式验证。**

验证：

```powershell
# 1. 编码正确、路径没被破坏（输出里不应有任何 '?'）
Get-Content 'data\launch-captured-*.cmd' -Encoding Default
# 2. `app\launch-diagnostics.cmd` 保持纯 ASCII + CRLF：
$b=[IO.File]::ReadAllBytes('app\launch-diagnostics.cmd')
($b | Where-Object { $_ -gt 127 }).Count   # 必须是 0
```

两个生成包装脚本的地方（`Start-DshCaptured` 与回退后的安装步骤）现在都会在
路径含 `?` 时**直接拒绝**，而不是生成一个指向别处的脚本。

### 3. `Guardian.exe.cs` 和 `.md` 文件**没有这个限制**

它们由 C# 编译器和文本编辑器按 UTF-8 处理，可以正常写中文。
`Guardian.exe.cs` 里的中文菜单就是这么写的。

### 4. 改完 `.cs` 要重新编译

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\DS\崩溃回退\app\build.ps1"
```
