# DSH Guardian 图形界面说明

本文只讲**图形界面（`dsh-guardian.exe`）**。命令行版本仍在 `dsh-guardian-console.exe`，
用法见 [README](../README.zh-CN.md#命令行用法可选)。

---

## 一、为什么换界面

旧版是控制台界面。它在这台机器上暴露出一类无法根治的问题：

- 它用底层控制台接口（绝对坐标写字、填色、滚动视口）**自己拼一屏**，
  而同一个控制台还有别的进程在写（快照脚本、监视器子进程），只要有一次错位，
  整屏文字就会跑到错误的行、甚至凭空消失。
- 鼠标命中靠"行号对行号"，而控制台的窗口与缓冲区尺寸会不同步，命中区域随之漂移。
- 中文是双宽字符，80 列的窗口里 20 行菜单经常折行、互相覆盖。

图形界面没有这些问题：**每个控件自己拥有自己的像素**，不存在坐标换算，
也不存在第二个写入者。所以这不是"修好了控制台"，而是**换掉了会出问题的那一层**。

---

## 二、界面构成

界面分成**三个带标题的区**，每个区的名字就说明它装什么：

```
┌ 当前状态 ─────────────────────────────────────────────┐  ← ① 现在守没守着
│ ○ 未监视   —— 不占用任何资源                          │
│ 上次检查：9 分钟前      回退目标：snap-…-known-good   │
│ 装插件前：先打开监视，并保持本窗口开着。              │
├ 操作 ─────────────────────────────────────────────────┤  ← ② 点这里干活
│ [打基线][开关监视][回退][日志][目录][刷新][退出]      │
├ 执行结果 ─────────────────────────────────────────────┤  ← ③ 点完看这里
│ ▶ 开始：打基线                                        │
│ Snapshot to create: …                                 │
│ ✔ 完成                                                │
└───────────────────────────────────────────────────────┘
```

两个对话框：

| 版本选择（点「回退」） | 数据目录（点「目录」） |
|---|---|
| ![版本选择](versions.png) | ![数据目录](browser.png) |

### ① 当前状态区

整个界面最重要的一句：**现在到底有没有在守着。**

| 显示 | 含义 | 颜色 |
|---|---|---|
| `● 监视中 —— 关掉本窗口即停止` | 监视器进程在跑，DSH 崩了会自动回退 | 绿 |
| `◐ 已开启，监视器启动中…` | 已下达开启指令，监视器还没报到 | 黄 |
| `○ 未监视 —— 不占用任何资源` | 什么都没跑 | 灰 |

> **关掉本窗口就会停止监视。** 监视器以 `-ParentPid <本窗口进程号>` 启动，窗口进程一消失它就自行退出
> （日志会记 `resident: exiting (launcher closed)`）。这是刻意的：程序不会在你不知情的情况下留在后台。
> 想继续监视就别关窗口。

### ② 操作区（7 个按钮）

每个动作一个按钮，**点一下直接执行**，不需要先选中再确认。

| 按钮 | 作用 |
|---|---|
| 打基线 | 把当前状态记为一个"好版本" |
| 开关监视 | 打开/关闭自动检查 |
| 回退 | 打开版本选择窗口：现在回退、只设为以后的目标，或删除 |
| 日志 | 看 `watchdog.log` 末尾 40 行 |
| 目录 | 打开内置文件浏览器 |
| 刷新 | 重新读取监视状态（等同 `F5`） |
| 退出 | 关闭窗口（等同 `Esc`） |

按钮文字用两字简称，**鼠标悬停会显示完整说明**。

> **早期版本这里同时有"动作列表"和"按钮"，两者调的是同一批动作**，
> 属于一个动作两个入口的界面缺陷。现在只保留按钮。

### ③ 执行结果区

点下按钮后会发生什么（即时反馈）：

以前点完按钮要等脚本跑完才有动静，界面看起来像卡死了。现在**点下去立刻有四处变化**：

| 位置 | 变化 |
|---|---|
| 状态行 | 变成 `⏳ 正在执行：打基线 …`（黄色） |
| 标题栏 | 变成 `DSH Guardian  执行中：打基线` |
| 鼠标 | 变成等待样式 |
| 本区 | 立刻出现 `▶ 开始：打基线`，并**自动滚到最新一行** |

动作结束后恢复原状，并追加一行结果：`✔ 完成` 或 `✖ 失败（退出码 N）`。
执行期间按钮会暂时禁用，避免重复点击。

本区内容：脚本的原始 stdout、错误信息、`▶ 开始` / `✔ 完成`。
深色等宽字体，可滚动。**这一区是排查问题的第一现场。**

## 三、每个动作具体做什么

### 打基线

把 DSH 现在这套配置记成一个"好版本"，之后崩溃可以退回到它。

- 实际动作：`dsh-snapshot.ps1 -Action Mark-Good`
- 会新建 `data\snapshots\snap-<日期时间>-known-good\`，并把它设为**回退目标**
- 旧的快照**永不删除、永不覆盖**
- **什么时候按**：装插件之前；装完插件确认 DSH 正常之后（再按一次，形成新基线）

### 开关监视

打开时：以独立进程启动监视器（`dsh-watchdog.ps1 -Resident -AutoRollback`），
它会按间隔探测 DSH 端口，判定"启动崩溃循环"后自动回退。

关闭时：先写暂停标记，再结束监视器进程并清理 `runtime.pid`。

- 打开后**可以关掉本窗口**，监视照常运行
- 监视器有寿命上限（默认 240 分钟），防止忘记关而永久驻留
- 想真正停止：GUI 里点「开关监视」关闭，或手工结束该进程

### 回退

弹出**版本选择窗口**（本程序自己的对话框，不依赖控制台）。这个窗口从上到下是：

```
┌──────────────────────────────────────────────────────────────┐
│ 选中一个版本：现在就回退、只设为以后的目标。要一次删除多个，  │
│ 打开右侧「多选」后勾选（多选仅对删除生效）。                  │
├──────────────────────────────────────────────────────────────┤
│ [全部] [最近 10 个] [仅基线]                    [ ] 多选      │
├─ 版本列表 ────────────────────────────┬──────────────────────┤
│ 版本              状态  抓取时间  插件 标签                    │
│ snap-20261003-004721   ←目标 2026-10-03 00:47  9  known-good  │
│ snap-20261002-230811         2026-10-02 23:08  9  非基线      │
├─ 包含插件 ────────────────────────────┴──────────────────────┤
│ deepseek-harness-plugin-xxx                                   │
│ …                                                             │
├──────────────────────────────────────────────────────────────┤
│ [现在就回退] [只设为以后的目标] [删除选中版本] [取消]          │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 作用 |
|---|---|
| 筛选按钮 | 全部 / 最近 10 个 / 仅基线 |
| **多选** 开关 | 打开后每行出现勾选框。**只影响「删除选中版本」** |
| 版本列表 | 五列：版本、状态（←目标）、抓取时间、插件数、标签 |
| **包含插件** | 显示选中版本**实际含有的插件名**，判断"这个版本有没有我要去掉的插件" |
| 分隔条 | 版本列表与包含插件之间**可拖动** |

| 按钮 | 效果 |
|---|---|
| 现在就回退 | 立刻把 DSH 配置还原到该版本（再弹一次确认框） |
| 只设为以后的目标 | 不动现在的配置，只改"崩了退到哪" |
| 删除选中版本 | 删除勾选（或未开多选时高亮）的快照，**窗口不关** |
| 取消 | 什么都不做 |

**回退前会自动留底**：当前配置先复制到 `data\snapshots\pre-restore-<时间>\`，
所以手动回退永远是可逆的。确认框里也写了这句话。

> 什么时候需要「只设为以后的目标」：先装了插件 A，又装了插件 B，B 把 DSH 搞崩了。
> 若目标是"装 A 之前"，回退会把 A 和 B 一起去掉；若目标是"装 B 之前"，只去掉 B。

#### 多选只对删除生效

「多选」是一个**模式开关**，不是常开行为：

| 开关 | 列表 | 「删除选中版本」删什么 |
|---|---|---|
| 关（默认） | 普通单选列表 | 当前高亮那一行 |
| 开 | 每行一个勾选框 | 所有勾选的行 |

- 「现在就回退」和「只设为以后的目标」**始终只作用于当前高亮的那一个**，与开关无关
- 关掉开关时**自动清空已勾选项**，不会留下看不见的选择
- 底部状态栏会写明当前模式：`共 13 个版本，已勾选 3 个（多选仅用于删除）`

#### 删除选中版本

这是本程序**唯一不可撤销**的操作，所以有四重保护：

1. **删除前单独确认**，确认框列出要删的快照名（超过 8 个则列前 8 个 + "共 N 个"）
2. **只允许删除 `snap-*` 目录**。`pre-restore-<时间>\` 这类留底目录**删不掉**——
   它们是回退失败后的补救手段，误删会让"退回上一次回退之前"变成不可能
3. **删完窗口不关**：列表自动重扫，可以接着删下一批，不用反复重开窗口
4. **自动维护回退目标**：
   - 删的不是当前目标 → 目标不动
   - 删的正是当前目标 → 目标**自动改为剩下的最新一个**，并在输出区写明
   - 删完最后一个 → 指针文件被清除，此时自动回退**拒绝回退**（没有可退的版本了），
     直到你重新打一个基线

取消确认或脚本失败时**列表不动**，不会出现"界面像是删掉了、其实没删"。

删除只影响磁盘上保留了什么，**不会动 DSH 现在的配置**。

命令行等价写法：

```powershell
powershell -File "app\dsh-snapshot.ps1" -Action Delete -Snapshot snap-20261002-232655-known-good
powershell -File "app\dsh-snapshot.ps1" -Action Delete -Snapshot "a,b"   # 多个，逗号分隔
powershell -File "app\dsh-snapshot.ps1" -Action Delete -Snapshot x -DryRun # 只列出会删什么
```

### 查看错误日志（「日志」按钮）

显示 `data\watchdog.log` 的**末尾 40 行**，包含 DSH 原始报错、崩溃判定过程、
回退记录、端口探测结果。崩了先看这里。

### 打开数据目录

弹出**程序内置的文件夹浏览器**（不调用资源管理器）：

```
┌──────────────────────────────────────────────────────────────┐
│ D:\DS\崩溃回退\data                        ← 当前路径         │
│ [数据根目录] [快照] [诊断报告] [刷新]      ← 快速跳转         │
├───────────────────────────┬──────────────────────────────────┤
│ 名称           大小  修改  │  选中文件的内容预览              │
│ [console]            23:08 │                                  │
│ [snapshots]          00:47 │  （目录不预览）                   │
│ crash-evidence-…json 227B  │                                  │
│ state.json          1 KB   │                                  │
│ watchdog.log        18 KB  │                                  │
├───────────────────────────┴──────────────────────────────────┤
│ [上一层] [打开] [关闭]        2 个目录，23 个文件             │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 说明 |
|---|---|
| 路径栏 | 当前所在目录的完整路径 |
| 快速跳转 | 一键到数据根目录 / `snapshots` / `诊断报告`；「刷新」重新读取 |
| **文件** | 三列：名称、大小、修改时间；`[方括号]` 是目录，蓝色显示 |
| **预览** | 选中**文件**即在右侧显示其内容；空文件、超过 200 KB 的文件只提示不预览 |
| 分隔条 | 文件与预览之间**可拖动**，按需要分配宽度 |
| **预览放大** | 一键把预览铺满整个窗口（再点变回「返回列表」），不用去找那条 6px 的分隔条 |
| 状态栏 | 当前目录下有多少个目录、多少个文件 |
| 快捷键 | `Enter` 打开选中项，`Backspace` 返回上一层，双击等同 Enter |

> 为什么不用资源管理器打开：这台机器上 `explorer.exe` 直接启动会报
> `0xc0000142`（应用程序无法正常启动），改用 Shell COM 又报"无法访问指定设备、路径或文件"。
> **同一个手段失败两次之后就不再试第三次**，改为程序自己显示——这也顺带解决了
> "只想看一眼日志却要开一个资源管理器窗口"的笨重。

### 刷新状态

重新读取 `mode.json`、`last-tick.json`、`last-known-good.json`、`runtime.pid`，
更新当前状态区。界面上这些信息**每 2 秒也会自动刷新一次**，此键用于立即刷新。

### 退出

点「退出」会**先询问，并明确告诉你监视会怎样**：

**未开启监视时**：只问一句"监视未开启，退出不会影响任何东西。确定退出？"

**监视正在运行时**，框里写明进程号，并告诉你会发生什么：

| 选择 | 结果 |
|---|---|
| 是 | **停止监视并退出**（监视器随之退出，`runtime.pid` 被清理） |
| 否 | 什么都不做，继续监视 |

> 早期版本的「退出」是一个什么都不说的 `Close()`：窗口凭空消失，用户不知道监视是被停了还是还在跑。
> 更早的一版还写着"选是＝保持监视，只关窗口"——那是**做不到的承诺**：监视器绑定在本窗口进程上，
> 窗口一关它必定退出，而用户会以为还在守着。现在文案说的是真实行为。

## 五、它和旧版（控制台）的关键区别

| | 控制台版 | 图形版 |
|---|---|---|
| 入口 | `dsh-guardian.exe` | `dsh-guardian.exe`（同一个名字，现在是图形界面） |

| 鼠标 | 行号命中，窗口尺寸一变就漂 | 原生控件，永远准 |

| 命令行动词 | 同一个 exe | 移到 `dsh-guardian-console.exe` |

## 六、常见问题

**窗口关了，监视还在跑吗？**
不在跑，已经停了。监视器绑定在本窗口进程上，窗口关闭它就退出（日志记 `resident: exiting (launcher closed)`）。
重新打开界面会显示 `○ 未监视`，需要再点一次「开关监视」。**这条是刻意的**：程序不会在你不知情时留在后台。

**为什么状态行显示"已开启，监视器启动中…"很久？**
监视器启动后需要一轮才会写入 `runtime.pid`。超过一分钟仍如此，
去看「日志」，或检查 `data\exe-trace.log`。

**「打开数据目录」里为什么没有资源管理器？**
见上文第 5 条——本机调用资源管理器失败过两次，所以改为程序自己显示。

**输出区出现 `[退出码 N]` 是什么意思？**
脚本返回了非零值。上面的原始输出就是原因；把这一段贴出来即可定位。

**反悔了怎么办？**
每次回退前都有 `pre-restore-<时间>\` 留底，用「回退」把它选回来即可。

**手动打基线和监视器自动回退会冲突吗？**
不会。监视器只用 `last-known-good.json` 指定的那一个目标；打基线会更新这个指针，
所以"装完插件确认正常 → 再打一次基线"就是正确的日常流程。
### 按钮点了没反应怎么查

程序会把界面上真正收到的每一次点击写进 `data\gui-clicks.log`。里面能看到：

| 日志行 | 含义 |
|---|---|
| `form loaded, action buttons=7` | 界面建好了，七个按钮都在 |
| `click: 打基线  busy=False actionsEnabled=True` | **点击确实到达了按钮** |
| `handler threw: …` | 点击到了，但动作内部抛异常（完整堆栈） |
| `selftest: entering RunAction(5)` | 动作开始执行 |

如果点完按钮这个文件里**没有** `click:` 那行，说明点击根本没送到按钮上
（不是动作的问题，是输入没到）；如果有 `click:` 但没有后续输出，那是动作本身出错。

这条日志是为"按钮无反应"这个具体故障加的：在此之前只能靠推理，而推理错过两次。
